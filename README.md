# دَفتَرچه

دفترچه‌ای برای اینکه بفهمی **الان چه کاری ارزش انجام دادن دارد** — یک اپ وب کامل، آفلاین‌پذیر و بدون حساب کاربری، برای کارهای روزانه، تمرکز، و خواندن.

داده‌ات روی دستگاه خودت می‌ماند؛ نه سروری برای حساب، نه همگام‌سازی ابری.

آدرس منتشرشده: <https://amirrezahajiabadi.github.io/daftarche/>

---

## قلمروهای اصلی

| بخش | چه می‌کند |
|---|---|
| **امروز** | صفحهٔ اول: سلام و تاریخ، افزودن سریع کار، پیشنهاد «الان چی کار کنیم؟» همراه با دلیل، کارهای امروز، پیشرفت امروز، حال‌وهوای روز. |
| **کارها** | اولویت، دسته‌بندی، مهلت، مدت تخمینی، یادآور، جستجو، فیلتر، مرتب‌سازی با درگ‌ودراپ، حذف با بازگردانی. |
| **تمرکز** | تایمر تمرکز با مدت قابل تنظیم، انتخاب کتاب برای جلسه، ثبت جلسه و امتیاز، ادامه دادن یک جلسهٔ نیمه‌کاره. |
| **سابقهٔ تمرکز** | جلسه‌های گذشته با عنوان کتاب، مدت، امتیاز و وضعیت تکمیل. |
| **بینش‌ها** | بازتاب آرام هفت‌روزه روی تمرکز و کارها، با آستانهٔ حداقل داده تا از نتیجه‌گیری زودهنگام پرهیز کند. |
| **کتابخانه** | قفسهٔ کتاب‌ها، هدف مطالعهٔ روزانه، درصد پیشرفت، صفحهٔ خوانده‌شده، قفسهٔ کتاب‌های تمام‌شده. |
| **خوانندهٔ PDF** | رندر با pdf.js، لایهٔ متن، انتخاب متن، هایلایت متن، هایلایت دست‌آزاد با سه ضخامت، پاک‌کن با بازگردانی، یادداشت، پیشرفت خواندن، و یک نوار ابزار پایین برای پیمایش صفحه، قلم، یادداشت‌ها و تنظیمات مطالعه. |
| **پروفایل و آمار** | نام و آواتار، روزهای پیاپی، نمودار هفتگی، مود روزانه، دستاوردها، تنظیمات تم و اعلان. |
| **اعلان‌ها** | یادآور محلی موعد کارها — سیستم اعلان رسمی نسخهٔ فعلی. Web Push زیرساخت اختیاری و موکول به آینده است (پایین را ببین). |

بخش‌های همراه: قورقوری (شخصیت راهنما)، تاسِ شانس برای انتخاب کار بعدی، صدای محیطی و موسیقی قابل بارگذاری.

## معماری

- **فرانت‌اند: JavaScript خالص و ماژولار.** بدون فریم‌ورک، بدون build step و بدون bundler. `index.html` یک `<script type="module">` را بار می‌گذارد و ماژول‌های `js/` با import استاندارد به هم وصل می‌شوند. CSS در حداکثر دسترس‌پذیری ساده و بدون پیش‌پردازش در پوشهٔ `css/` است.
- **حالت برنامه:** یک store سادهٔ مرکزی (`js/state.js`) با یک گذرگاه رویداد (`js/bus.js`)؛ رندر هر صفحه به‌صورت imperative و مستقل است.
- **تاریخ شمسی:** تبدیل‌های تاریخ در `js/jalali.js`، بدون وابستگی بیرونی.

## ذخیره‌سازی

همهٔ داده‌های کاربر محلی است و در همین مرورگر می‌ماند.

| داده | محل |
|---|---|
| کارها، نام، تم، تاریخ روزهای فعال، مودها، تنظیمات تمرکز، جلسهٔ در جریان، سابقهٔ تمرکز | `localStorage` (کلیدهای `daftarche-*`) |
| متادیتای کتاب‌ها (پیشرفت، صفحه‌های خوانده‌شده، هدف، هایلایت‌ها، یادداشت‌ها) | `localStorage` |
| فایل PDF کتاب‌ها | `IndexedDB` — دیتابیس `daftarche-books`، store `books` |
| موسیقی‌هایی که خودت بارگذاری می‌کنی | `IndexedDB` — دیتابیس `daftarche-audio`، store `tracks` |

«پاک کردن همهٔ داده‌ها» در پروفایل، دادهٔ کاربر را پاک می‌کند: هر دو دیتابیس IndexedDB (کتاب‌ها و موسیقی بارگذاری‌شده) و `localStorage`. کش آفلاین، ثبت Service Worker و مجوز اعلان‌ها دست‌نخورده می‌مانند. اگر پاک‌سازی کامل نشود، برنامه پیام خطای صریح می‌دهد.

فایل‌های PDF هرگز از کش مرورگر رد نمی‌شوند؛ فقط خود اپ در کش آفلاین ذخیره می‌شود.

## PWA

- **نصب‌پذیری:** `manifest.webmanifest` با `display: standalone`، `start_url` و `scope` نسبی، و آیکون‌های `any` و `maskable`. رنگ نوار مرورگر از `theme-color` می‌آید و با تم فعال (روشن/تاریک) هماهنگ می‌شود.
- **پوستهٔ آفلاین:** `sw.js` فهرست `SHELL` را در زمان نصب به‌صورت یک مجموعه کش می‌کند — صفحه، همهٔ CSS و ماژول‌های JS، فونت‌ها، آیکون‌ها و تصویرهای شخصیت‌ها. اپ بدون شبکه هم بالا می‌آید.
- **کش هر انتشار:** نام کش‌ها از نسخهٔ build ساخته می‌شود (`daftarche-static-<BUILD>` و `daftarche-runtime-<BUILD>`). یک انتشار به‌صورت یک کلیت اعمال می‌شود؛ هرگز نیمه‌قدیم و نیمه‌جدید سرو نمی‌شود.
- **pdf.js:** نسخهٔ پین‌شدهٔ pdf.js از CDN با استراتژی cache-first در کش runtime نگه داشته می‌شود تا خواننده آفلاین هم کار کند. فایل‌های کمکی آن (cmaps و فونت‌های استاندارد) در صورت نیاز کش می‌شوند.
- **سازگاری ریشه و زیرمسیر:** همهٔ مسیرها نسبت به مکان خود فایل resolve می‌شوند، پس اپ هم روی `https://domain/` و هم روی زیرمسیری مثل `https://domain/daftarche/` درست کار می‌کند — از جمله مقصد کلیک اعلان‌ها، آیکون و badge آن‌ها.
- **به‌روزرسانی:** هیچ‌وقت اجباری نیست. کارگر جدید بی‌صدا نصب می‌شود و فقط وقتی جایگزین می‌شود که صفحه اجازه بدهد (تپ روی اعلان به‌روزرسانی) یا در پس‌زمینه و وقتی برگه پنهان است.

## نسخه‌گذاری و انتشار

**تنها محل نوشتن شمارهٔ نسخه: `js/version.js`.**

```js
self.DAFTARCHE_RELEASE = '2.0.0';   // نسخهٔ محصول
self.DAFTARCHE_BUILD   = 'v15';     // نسخهٔ build آفلاین
```

| مفهوم | یعنی چه | کجا مصرف می‌شود |
|---|---|---|
| `RELEASE` | نسخهٔ محصول که کاربر می‌بیند (مثل `2.0.0`). | برچسب نسخه در تنظیمات پروفایل، دیالوگ «چی تغییر کرد؟»، ورودی `CHANGELOG` در `js/changelog.js`، و سابقهٔ `CHANGELOG.md`. |
| `BUILD` | نام build آفلاین؛ کلید کش‌های Service Worker. | نام هر دو کش، و اینکه کارگر جدید اصلاً نصب شود یا نه. |

قواعد:

1. **هر تغییری در فایل‌های پوسته، `BUILD` را جلو می‌برد.** فایل‌های پوسته همان فهرست `SHELL` در `sw.js` است: `index.html`، `manifest.webmanifest`، همهٔ `css/`، همهٔ `js/` (شامل خود `js/version.js`) و دارایی‌های فونت/آیکون/شخصیت.
2. **`RELEASE` در همان فایل جلو می‌رود** و همراه آن یک ورودی به `CHANGELOG` در `js/changelog.js` (برای دیالوگ درون‌برنامه‌ای) و یک بخش در `CHANGELOG.md` (برای سابقهٔ انتشار) اضافه می‌شود.
3. `sw.js` این فایل را با `importScripts` می‌خواند و خودش شمارهٔ مستقل ندارد. صفحه هم همان را با یک `<script>` کلاسیک پیش از ورودی ماژول می‌خواند. پس نسخهٔ محصول، نسخهٔ کش و نسخهٔ Service Worker **از هم جدا نیستند** و نمی‌توانند از هم فاصله بگیرند.
4. **انتشار بدون بالا بردن `BUILD` عمداً به کاربران نصب‌شده تحمیل نمی‌شود.** برنامه نصب‌شده همان build منسجم قبلی را نگه می‌دارد تا وقتی `BUILD` عوض شود. اگر فایلی از پوسته را تغییر بدهی و `BUILD` را جلو نبری، آن تغییر به client نصب‌شده نمی‌رسد (به بازدید تازه می‌رسد).

### چرخهٔ به‌روزرسانی

```
deploy → مرورگر sw.js را تازه می‌گیرد (updateViaCache: 'none')
       → BUILD عوض شده ⇒ install: کش کاملِ build جدید ساخته می‌شود
       → activate: کش‌های daftarche-* قدیمی حذف می‌شوند
       → صفحه اعلان به‌روزرسانی را نشان می‌دهد (یا در پس‌زمینه بی‌صدا تحویل می‌شود)
       → بعد از تعویض کارگر، صفحه یک بار reload می‌شود
```

اگر فقط `RELEASE` جلو رفته باشد و هیچ فایل پوسته‌ای عوض نشده باشد، نصب دوباره کل کش را دانلود نمی‌کند و فقط نشانگر نسخه را تازه می‌کند.

### چک‌لیست پیش از انتشار

1. تغییرات محصول کامل شود.
2. QA انجام شود.
3. در `js/version.js`: `RELEASE` (و اگر فایلی از پوسته عوض شده، `BUILD`) به‌روزرسانی شود.
4. ورودی `js/changelog.js` و بخش `CHANGELOG.md` اضافه شود.
5. انتشار انجام شود.
6. به‌روزرسانی Service Worker بررسی شود: اعلان به‌روزرسانی بیاید، پس از تعویض کارگر نسخهٔ جدید سرو شود و کش قدیمی حذف شده باشد.

## Web Push — جزء اختیاری سرور

یادآورهای محلی در خود اپ کار می‌کنند و برای آن‌ها هیچ سروری لازم نیست. کنار آن، یک لایهٔ **اختیاری** Web Push وجود دارد:

- سمت کلاینت: `js/notifications.js` یادآور محلی را از تپ روی زنگ کار زمان‌بندی می‌کند. ماژول `js/push-service.js` نگه داشته شده اما در انتشار فعلی خاموش است؛ نه اشتراکی ساخته می‌شود و نه درخواستی به سرور push می‌رود.
- سمت سرور: پوشهٔ `server/` — یک سرویس Express که اشتراک‌ها را نگه می‌دارد و یادآورهای موعد را با VAPID می‌فرستد. مستندات کامل در [`server/README.md`](server/README.md).
- اگر سرور در دسترس نباشد، Web Push بی‌صدا خاموش می‌ماند و یادآورهای محلی تنها کار می‌کنند.

وضعیت فعلی، صریح:

- این لایه در انتشار فعلی **قابلیت محصول نیست**: خاموش است و به آینده موکول شده. تکمیل آن به یک زمان‌بند بیرونی و معماری همگام‌سازی کارها فراتر از local-first فعلی نیاز دارد؛ بدون آن حتی اشتراکی هم ساخته نمی‌شود.
- میزبانی استاتیک (مثل GitHub Pages) **خودش زمان‌بند ندارد**؛ برای یادآورهای موعد، یک زمان‌بند بیرونی (cron) باید endpoint سرور را صدا بزند. بدون آن، هیچ اعلان push ارسال نمی‌شود.
- کلیدهای VAPID و `ADMIN_API_KEY` فقط از محیط سرور تزریق می‌شوند و هرگز در فرانت‌اند، گیت یا لاگ قرار نمی‌گیرند.

## اجرای محلی

اپ ماژول ES و Service Worker دارد، پس با باز کردن مستقیم فایل (`file://`) کار نمی‌کند و به یک سرور استاتیک روی HTTP نیاز دارد:

```bash
python -m http.server 8000
# سپس http://127.0.0.1:8000/
```

برای آزمایش روی زیرمسیر، همان پوشه را داخل یک زیرپوشه بگذار و از `http://127.0.0.1:8000/daftarche/` باز کن.

سرور اختیاری Push:

```bash
cd server
npm install
npm run keys      # ساخت جفت کلید VAPID (یک‌بار)
npm start
```

```text
  state.js / store.js   حالت مرکزی و ماندگاری
  today.js / tasks.js   صفحهٔ امروز و کارها
  decision.js           موتور تصمیم (امتیازدهی قطعی، بدون DOM)
  decisioncontext.js    زمینهٔ تصمیم و حلقهٔ یادگیری
  focus.js / focushistory.js   تمرکز و سابقهٔ آن
  insights.js / week.js        بینش‌ها و آمار هفتگی
  library.js / reader.js       کتابخانه و خوانندهٔ PDF
  notifications.js / push-service.js   یادآور محلی و Web Push
  characters             qorqori, jingool, khabalo, fekrbaz, rizolo
assets/                 فونت‌ها، آیکون‌ها، تصویرهای شخصیت‌ها

```
